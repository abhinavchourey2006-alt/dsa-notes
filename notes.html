Unit I: Notion of Algorithm, Problem Solving & Asymptotic Notations

Unit I establishes how algorithms are defined, designed, and measured independently of hardware or programming language.

1. Introduction & Notion of an Algorithm

An algorithm is a finite sequence of unambiguous instructions for solving a problem—producing a required output for any legitimate input in a finite amount of time. Unlike a computer program (which is written in a specific language), an algorithm is an abstract step-by-step method.

  • Input: Zero or more quantities are externally supplied from a specified set of valid inputs.
  • Output: At least one quantity is produced as the result.
  • Definiteness (Unambiguity): Every step must be crystal clear with a single, exact meaning.
  • Finiteness: The algorithm must terminate after a finite number of steps for all valid inputs.
  • Effectiveness: Every instruction must be basic enough to be carried out in principle with pencil and paper in finite time.

2. Fundamentals of Algorithmic Problem Solving

Designing a reliable algorithm follows eight sequential stages:

  1. Understand the problem: Read carefully, identify the input domain, and check special/edge cases.
  2. Ascertain computational device capabilities: Decide between sequential execution (RAM model—one instruction at a time) and parallel execution, and note memory/speed limits.
  3. Choose exact vs. approximate solving: Use exact algorithms when exact answers exist (sorting, shortest path); use approximation when exact calculation is impossible (continuous math like roots/integrals) or too slow (NP-hard problems).
  4. Decide on data structures: Select arrays, linked lists, stacks, queues, trees, heaps, or graphs that best fit the algorithm's dominant operations.
  5. Design the algorithm: Choose a design paradigm (Brute Force, Divide & Conquer, Greedy, Dynamic Programming, Backtracking) and write pseudocode.
  6. Prove correctness: Prove that the algorithm gives the right output for all valid inputs in finite time, typically via mathematical induction or loop invariants.
  7. Analyze the algorithm: Evaluate time efficiency (how fast it runs), space efficiency (extra memory used), and simplicity.
  8. Code and test: Implement in a programming language and verify against boundary cases.

3. Important Problem Types

  • Sorting: Rearranging elements in ascending or descending order (Merge Sort, Quick Sort, Heap Sort).
  • Searching: Finding a search key in a collection (Sequential Search, Binary Search, Hashing).
  • String Processing: Manipulating character sequences, especially pattern matching (Brute-Force String Matching).
  • Graph Problems: Modeling networks of vertices and edges to find paths, cycles, or spanning trees (BFS, DFS, Dijkstra, Prim, Kruskal).
  • Combinatorial Problems: Finding a permutation, combination, or subset that optimizes an objective (Traveling Salesman, Knapsack, Subset-Sum).
  • Geometric Problems: Working with points, lines, and polygons (Closest-Pair, Convex Hull).
  • Numerical Problems: Solving continuous mathematical problems using discrete approximations (equations, integrals).

4. Fundamentals of the Analysis Framework

  • Measuring Input Size (n): Efficiency is expressed as a function of input size n—such as the number of elements in an array, matrix dimension n×n, number of vertices/edges in a graph, or bit length b = ⌊log₂ n⌋ + 1 for integer algorithms.
  • Basic Operation & Running Time: Instead of wall-clock seconds (which vary by CPU and compiler), we count executions of the basic operation—the most time-consuming operation inside the innermost loop (usually a key comparison or multiplication). Total time is T(n) ≈ c_op · C(n).
  • Orders of Growth: For large n, only the dominant term matters; constant multipliers and lower-order terms are ignored (e.g., 4n² + 15n + 7 grows proportionally to n²).
  • Worst-Case, Best-Case, Average-Case: Worst-case C_worst(n) gives the maximum steps for any input of size n (guarantees an upper bound). Best-case C_best(n) gives the minimum steps. Average-case C_avg(n) gives the expected steps over a random input distribution.

5. Asymptotic Notations & Basic Efficiency Classes

  • Big-O — O(g(n)) (Upper Bound): t(n) ∈ O(g(n)) if there exist constants c > 0 and n₀ ≥ 0 such that t(n) ≤ c·g(n) for all n ≥ n₀. Used for worst-case upper bounds. Example: 3n + 5 ∈ O(n) with c = 4, n₀ = 5.
  • Big-Omega — Ω(g(n)) (Lower Bound): t(n) ∈ Ω(g(n)) if there exist constants c > 0 and n₀ ≥ 0 such that t(n) ≥ c·g(n) for all n ≥ n₀. Used for lower bounds. Example: n² + 2n ∈ Ω(n²) with c = 1, n₀ = 0.
  • Big-Theta — Θ(g(n)) (Tight Bound): t(n) ∈ Θ(g(n)) if there exist constants c₁, c₂ > 0 and n₀ ≥ 0 such that c₁·g(n) ≤ t(n) ≤ c₂·g(n) for all n ≥ n₀. Used when upper and lower bounds match.

Unit II: Mathematical, Empirical & Visual Analysis

Unit II teaches how to convert loops into summations and recursive calls into recurrence relations, plus how to test algorithms empirically.

1. Mathematical Analysis of Non-Recursive Algorithms

Follow this five-step plan for loop-based algorithms:

  1. Decide on parameter n indicating input size.
  2. Identify the basic operation inside the innermost loop.
  3. Check whether the basic operation count depends only on n (if not, analyze worst, best, and average cases separately).
  4. Set up a summation expressing the total basic operation count.
  5. Simplify the summation using standard closed-form formulas:
∑_{i=l}^{u} 1 = u - l + 1       ∑_{i=1}^{n} i = n(n+1)/2 ∈ Θ(n²)       ∑_{i=1}^{n} i² = n(n+1)(2n+1)/6 ∈ Θ(n³)

Worked Example — Element Uniqueness: Check if all elements in A[0..n-1] are distinct.

Algorithm UniqueElements(A[0..n-1])
  for i ← 0 to n - 2 do
    for j ← i + 1 to n - 1 do
      if A[i] = A[j] then return false
  return true

Worst-Case Comparisons (all elements distinct):
C_worst(n) = ∑_{i=0}^{n-2} ∑_{j=i+1}^{n-1} 1 = ∑_{i=0}^{n-2} (n - 1 - i) = (n - 1)n / 2 ∈ Θ(n²)

2. Mathematical Analysis of Recursive Algorithms

Follow this five-step plan for recursive algorithms:

  1. Decide on input size parameter n.
  2. Identify the basic operation.
  3. Check if worst/best/average cases differ.
  4. Set up a recurrence relation with an appropriate initial condition.
  5. Solve the recurrence using backward substitution or the Master Theorem.

Worked Example — Recursive Factorial:

Algorithm Fact(n)
  if n = 0 return 1
  else return Fact(n - 1) * n

Basic Operation: Multiplication (*)
Recurrence: M(n) = M(n - 1) + 1  for n > 0,   Initial condition: M(0) = 0
Backward substitution:
M(n) = M(n - 1) + 1
     = [M(n - 2) + 1] + 1 = M(n - 2) + 2
     = [M(n - 3) + 1] + 2 = M(n - 3) + 3
     ...
     = M(n - n) + n = M(0) + n = n ∈ Θ(n)

3. Example: Fibonacci Numbers

The Fibonacci sequence is 0, 1, 1, 2, 3, 5, 8, ... defined by F(n) = F(n - 1) + F(n - 2) with F(0) = 0, F(1) = 1.

  • Naive Recursive Algorithm: if n ≤ 1 return n; else return Fib(n-1) + Fib(n-2). The recurrence for additions is A(n) = A(n - 1) + A(n - 2) + 1 with A(0) = A(1) = 0. Solving this yields A(n) ∈ Θ(φⁿ) where φ = (1 + √5)/2 ≈ 1.618. It is exponential because the recursion tree recomputes the same values (e.g., F(2), F(1)) repeatedly.
  • Iterative (Non-Recursive) Algorithm: Store two variables a = 0, b = 1 and iterate from 2 to n updating c = a + b; a = b; b = c. This runs in Θ(n) time and Θ(1) space.

4. Empirical Analysis & Algorithm Visualization

Empirical Analysis tests an implemented program on real inputs when mathematical analysis is too hard or when comparing constant factors. Steps: (1) understand the experiment's goal, (2) choose metric M (CPU time in ms or basic-op counter), (3) decide input characteristics (range of n, random vs. sorted), (4) implement and generate sample inputs, (5) run and record results, and (6) plot data to observe growth behavior.

Algorithm Visualization uses graphics to illustrate algorithm behavior. Static visualization shows still snapshots at key moments (e.g., array states after each pass); Dynamic visualization (animation) shows continuous step-by-step execution. It is used in education to build intuition and in software engineering to debug or spot bottlenecks.

1. Brute Force Algorithms

Brute force solves a problem straightforwardly, directly following the problem statement.

Selection Sort

Scans the unsorted subarray A[i..n-1] to find the smallest element and swaps it with A[i].

SelectionSort(A[0..n-1]):
  for i ← 0 to n - 2 do
    min ← i
    for j ← i + 1 to n - 1 do
      if A[j] < A[min] then min ← j
    swap A[i] and A[min]
// Comparisons: ∑_{i=0}^{n-2} (n - 1 - i) = n(n-1)/2 ∈ Θ(n²); Swaps: n - 1

Bubble Sort

Repeatedly compares adjacent elements and swaps them if out of order, bubbling the largest element to the end on each pass. Adding a swapped flag lets it stop early on sorted arrays.

BubbleSort(A[0..n-1]):
  for i ← 0 to n - 2 do
    swapped ← false
    for j ← 0 to n - 2 - i do
      if A[j+1] < A[j] then
        swap A[j] and A[j+1]
        swapped ← true
    if not swapped then break
// Worst/Avg: n(n-1)/2 ∈ Θ(n²); Best (sorted): n - 1 ∈ Θ(n)

Sequential Search & Brute-Force String Matching

Sequential Search: Scans A[0..n-1] left to right until key K is found or end is reached. Best case O(1), worst case O(n), average case ≈ n/2 ∈ Θ(n).

Brute-Force String Matching: Aligns pattern P[0..m-1] against text T[0..n-1] at each shift i = 0..n-m and checks characters left to right. Worst case (e.g., T = "AAAA...B", P = "AAB") performs m(n - m + 1) ∈ O(nm) comparisons.

2. Divide & Conquer, Binary Trees & Decrease & Conquer

Divide & Conquer splits a problem into smaller subproblems of the same type, solves them recursively, and combines their solutions.

Merge Sort & Recurrence Derivation

MergeSort(A[0..n-1]):
  if n > 1 then
    copy A[0..⌊n/2⌋-1] to B; copy A[⌊n/2⌋..n-1] to C
    MergeSort(B); MergeSort(C)
    Merge(B, C, A)   // at most n - 1 comparisons

Worst-Case Recurrence (assume n = 2^k):
C(n) = 2C(n/2) + n - 1,  C(1) = 0
Approximating n - 1 ≈ n:
C(2^k) = 2C(2^{k-1}) + 2^k
       = 2[2C(2^{k-2}) + 2^{k-1}] + 2^k = 2²C(2^{k-2}) + 2·2^k
       = 2^k C(1) + k·2^k = 0 + (log₂ n)·n ∈ Θ(n log n)

Quick Sort

Selects a pivot and partitions the array so elements ≤ pivot lie on the left and ≥ pivot lie on the right, then sorts both subarrays recursively. Best/Average case is Θ(n log n); Worst case (already sorted array with first/last element as pivot) is Θ(n²).

Binary Search & Recurrence Derivation

Searches a sorted array by comparing key K with middle element A[m] and discarding half the array each step.

Recurrence: C_worst(n) = C_worst(⌊n/2⌋) + 1,  C_worst(1) = 1
For n = 2^k:
C(2^k) = C(2^{k-1}) + 1 = C(2^{k-2}) + 2 = ... = C(1) + k = 1 + log₂ n ∈ Θ(log n)

Binary Tree Traversals & Properties

  • Preorder: Root → Left → Right (used to copy/serialize a tree).
  • Inorder: Left → Root → Right (produces sorted ascending order on a Binary Search Tree).
  • Postorder: Left → Right → Root (used to delete a tree or evaluate expression trees).
  • Key Properties: A binary tree with n internal nodes has n + 1 external (null) nodes; height h satisfies ⌊log₂ n⌋ ≤ h ≤ n - 1.

Decrease & Conquer: Insertion Sort

Reduces problem size by 1 each step: assumes A[0..i-1] is sorted and inserts A[i] into its correct position by shifting larger elements right. Best case (sorted) is Θ(n); worst/average case is Θ(n²). Ideal for nearly sorted arrays.

Unit IV: Transform & Conquer, AVL Trees, Heaps & Dynamic Programming

1. Presorting & AVL Trees

Presorting (Instance Simplification): Sorting an array first in Θ(n log n) makes many problems trivial—for example, checking element uniqueness drops from Θ(n²) to Θ(n log n) (just scan adjacent elements), and finding the mode becomes a single linear pass.

AVL Trees (Balanced Search Trees): An AVL tree is a Binary Search Tree in which every node's Balance Factor BF = height(Left) - height(Right) must be -1, 0, or +1. This guarantees O(log n) height and lookup. When an insertion makes |BF| = 2 at the nearest ancestor z, rebalance using one of four rotations:

  • LL Rotation (Single Right): New node inserted in Left subtree of Left child of z → perform one right rotation at z.
  • RR Rotation (Single Left): New node inserted in Right subtree of Right child of z → perform one left rotation at z.
  • LR Rotation (Double): New node inserted in Right subtree of Left child → left-rotate the left child, then right-rotate z.
  • RL Rotation (Double): New node inserted in Left subtree of Right child → right-rotate the right child, then left-rotate z.

2. Dynamic Programming: Warshall's & Floyd's

Dynamic Programming solves overlapping subproblems bottom-up and stores intermediate results in a table.

Warshall's Algorithm (Transitive Closure): Computes reachability matrix R of a directed graph (R[i,j] = 1 if a directed path exists from i to j):

for k ← 1 to n do
  for i ← 1 to n do
    for j ← 1 to n do
      R[i, j] ← R[i, j] OR (R[i, k] AND R[k, j])

Floyd's Algorithm (All-Pairs Shortest Paths): Computes shortest path distance matrix D between every pair of vertices in a weighted graph (no negative cycles):

for k ← 1 to n do
  for i ← 1 to n do
    for j ← 1 to n do
      D[i, j] ← min(D[i, j],  D[i, k] + D[k, j])

Both algorithms run in Θ(n³) time and Θ(n²) space.

3. Heaps & Heap Sort

A Heap is a complete binary tree stored compactly in an array A[1..n] where node i has parent ⌊i/2⌋, left child 2i, and right child 2i + 1.

Property Min-Heap Max-Heap
Heap-Order Rule A[parent] ≤ A[child] A[parent] ≥ A[child]
Root Element Smallest element Largest element
Primary Use Priority Queue, Dijkstra, Prim Heap Sort (ascending)
Example Array [2, 5, 8, 10, 9] [10, 9, 8, 5, 2] 
Heapify(A, i, n):   // restores Max-Heap at index i
  largest ← i; l ← 2i; r ← 2i + 1
  if l ≤ n and A[l] > A[largest] then largest ← l
  if r ≤ n and A[r] > A[largest] then largest ← r
  if largest ≠ i then
    swap A[i] and A[largest]
    Heapify(A, largest, n)

HeapSort(A, n):
  // Phase 1: Build Max-Heap bottom-up in O(n)
  for i ← ⌊n/2⌋ downto 1 do Heapify(A, i, n)
  // Phase 2: Swap root with end & heapify (n - 1) times
  for i ← n downto 2 do
    swap A[1] and A[i]
    Heapify(A, 1, i - 1)
// Time: O(n) + (n - 1)·O(log n) ∈ Θ(n log n); Space: O(1)

Unit V: Backtracking, Branch & Bound & Complexity Classes

Unit V handles NP-hard combinatorial problems by systematically searching state-space trees and pruning hopeless branches early.

1. Backtracking (Depth-First State-Space Search)

Backtracking builds solutions one component at a time using a state-space tree (DFS). If a partial solution violates a constraint (non-promising node), it prunes that subtree immediately and backtracks to the parent.

  • n-Queen's Problem: Place n queens on an n×n chessboard so no two attack each other. Place one queen per row r in column c such that no earlier queen shares the same column (cᵢ ≠ cⱼ) or diagonal (|rᵢ - rⱼ| ≠ |cᵢ - cⱼ|).
  • Hamiltonian Circuit Problem: Find a simple cycle in a graph G = (V, E) that visits every vertex exactly once and returns to the start vertex. At step k, only choose a vertex adjacent to v_{k-1} that has not been visited yet (and at step n, it must connect back to v₁).
  • Subset-Sum Problem: Given positive integers S = {w₁, ..., wₙ} sorted ascending and target d, build a binary tree (left = include wᵢ, right = exclude wᵢ). Prune if current_sum + wᵢ > d or current_sum + remaining_sum < d.

2. Branch and Bound (Best-First Optimization Search)

Unlike backtracking (which stops at any valid solution or checks all), Branch and Bound solves optimization problems by computing a numerical bound (lower bound for minimization, upper bound for maximization) for every node and expanding the most promising node first (best-first search). A branch is pruned if its bound is worse than the best solution already found.

  • Assignment Problem: Assign n jobs to n people with minimum total cost. Lower bound at any node = cost assigned so far + sum of minimum costs in each remaining unassigned row.
  • 0/1 Knapsack Problem: Maximize value within capacity W. Sort items by value-to-weight ratio vᵢ/wᵢ descending. Upper bound = v + (W - w)(v_{i+1}/w_{i+1}).
  • Traveling Salesman Problem (TSP): Find shortest tour visiting all cities once. Lower bound = half the sum of the two smallest edges incident to each vertex (or via reduced cost matrix).

3. Complexity Classes: P, NP, and NP-Complete

  • Class P (Polynomial Time): Decision problems solvable in polynomial time O(n^k) by a deterministic algorithm. Examples: Binary Search, Merge Sort, Shortest Path (Dijkstra).
  • Class NP (Nondeterministic Polynomial Time): Decision problems whose proposed solution can be verified in polynomial time. Every problem in P is also in NP (P ⊆ NP). Examples: Graph Coloring, Integer Factorization.
  • Class NP-Complete: The hardest problems in NP—every problem in NP can be reduced to an NP-Complete problem in polynomial time. If any NP-Complete problem is solved in polynomial time, then P = NP. Examples: 3-SAT, Hamiltonian Circuit, 0/1 Knapsack, TSP (decision).
